# Anonymizer

Локальное приложение для поиска и маскировки персональных данных в тексте. Пользователь проверяет найденные фрагменты, исправляет разметку и при наличии своего корпуса может дообучать модель.

## Что можно оценить

В репозитории есть приложение и готовая CPU-модель `ru-pii` версии `0.1.0`. На чистой базе приложение проверяет SHA-256 артефакта и устанавливает модель активной. Для первого запуска исходный обучающий корпус не нужен.

Весовой файл — `anonymizer_code/backend/app/artifacts/ru-pii-base-0.1.0.npz`, рядом лежит JSON-манифест с версией токенизатора, контрольной суммой, категориями и агрегированными метриками. NPZ хранит категории и численные коэффициенты в хешированном признаковом пространстве; строки обучающего корпуса туда не записываются. Исходные записи корпуса в репозитории отсутствуют.

Модель обучена на синтетических данных. Ниже приведён точный entity-span F1: предсказанный фрагмент должен совпасть с правильной меткой и обеими границами.

| Выборка | Precision micro | Recall micro | F1 micro |
| --- | ---: | ---: | ---: |
| Validation | 0,590 | 0,743 | 0,658 |
| Отложенный test | 0,596 | 0,749 | 0,664 |

Это экспериментальная базовая модель. На validation слабее всего сработали `ORG` (F1 0,203), `INSTITUTION` (0,259), `DISEASE` (0,563) и `PER` (0,628). Результаты не подтверждают качество на реальных медицинских и юридических документах, сканах или OCR.

## Категории и эпонимы

Модель размечает 17 категорий:

- Люди и контакты: `PER`, `PHONE`, `EMAIL`.
- Идентификаторы: `PASSPORT`, `SNILS`, `INN`, `KPP`, `OGRN`.
- Адреса и география: `COUNTRY`, `REGION`, `LOCALITY`, `STREET`, `HOUSE`, `APART`.
- Организации и учреждения: `ORG`, `INSTITUTION`.
- Болезни: `DISEASE`.

Отдельной метки `EPONYM` нет. Метка зависит от того, что обозначает слово в конкретном тексте: фамилия человека относится к `PER`, название болезни — к `DISEASE`, географическое имя — к соответствующей географической категории. Совпадение со словом вроде «Сметана», «Мирный», «Король» или «Финк» само по себе не делает его персональными данными. Контекстные эпонимы остаются сложным случаем и требуют проверки человеком.

На проверочных фразах базовая модель выделяет «болезнь Бехтерева» как `DISEASE`, фамилию в «Иван Сметана» как `PER` и оставляет слово «сметана» в бытовом предложении без метки `PER`. В короткой фразе «в посёлке Мирный живёт Ангел Король» она ошибочно считает «Мирный» именем человека; в предложении «Пациентка Мария Андреевна Белова приехала из Казани» она также ошибочно размечает «Казани» как `PER`. Эти примеры показывают, почему результаты нужно проверять и исправлять.

## Локальный запуск

Требуются Docker Desktop и PowerShell. Из корня репозитория выполните:

```powershell
Set-Location anonymizer_code
Copy-Item .env.example .env
```

Откройте `.env` и задайте собственные значения для `POSTGRES_PASSWORD`, `APP_PASSWORD` и `SESSION_SECRET` (не короче 32 символов). Для локального адреса оставьте `APP_ORIGIN=http://localhost:8080` и `COOKIE_SECURE=false`. Файл `.env` остаётся локальным.

```powershell
docker compose up --build -d
```

Откройте <http://localhost:8080> и войдите с именем и паролем из `.env`. По умолчанию веб-интерфейс привязан к `127.0.0.1`. API и PostgreSQL наружу не публикуются. Вставьте тестовый текст, запустите анализ, проверьте фрагменты и примените маскировку.

Артефакт проверяется при запуске API. Установка выполняется только когда база данных ещё не содержит модели `ru-pii`; существующие пользовательские модели не заменяются. Модель хранится в локальной базе PostgreSQL. Остановка контейнеров не удаляет её, пока сохраняется volume `postgres_data`.

## Дообучение на своих данных

Исходный корпус в комплект не входит. Для переобучения загрузите собственный корпус из вкладки модели в поддерживаемом формате с отдельными `train`, `validation` и `test` split-ами. Train используется для подгонки весов, validation — для метрик; test остаётся отложенной проверкой.

Worker и API уже содержат веса модели версии 2. Новая задача использует активные веса как начальные коэффициенты, если активная модель совместима с токенизатором v2. При наличии локального корпуса автоматический запуск обучения накапливает проверенные аннотации до порога `AUTO_TRAIN_MIN_NEW_EXAMPLES` (по умолчанию 100). Созданная версия остаётся кандидатом, её можно проверить и активировать из интерфейса.

Тексты и пользовательские аннотации сохраняются в локальной базе данных. Настройте доступ к базе и резервным копиям; используйте для демонстрации синтетический текст.
