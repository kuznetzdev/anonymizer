# Внешняя синтетика и план контрастных примеров для NER 1.17.0+

Проверка первичных карточек и лицензий выполнена 2026-10-21. Из scanpatch скачаны два parquet-файла только в локальную ignored-папку для аудита; их строки не копировались и не добавлялись в репозиторий или обучающие данные. Остальные источники изучались по публичным карточкам и документации. Наличие MIT или CC BY 4.0 само по себе не подтверждает качество разметки.

### Проверка scanpatch, закреплённая ревизия

На 2026-10-21 карточка и Dataset Viewer показывают 4 786 train + 532 test, 27 типов и MIT. Проверена ревизия `6af0587dde068d90d8a1080285159c374b46a09b`; скачанные в игнорируемую audit-папку parquet-файлы имеют SHA-256: train `8e742bf0d39d4db7f2eb1f6c6b6cf9480536769ab31bcfbc6cd986fd1a3be37e`, test `5d44f419692282285ae811bd54b69e57bb44121e31f3628408e203f9416371ba`. В файлах репозитория есть README с полем `license: mit`, отдельного `LICENSE` файла нет; это следует прояснить до включения. Карточка говорит об управляемой синтетической генерации по шаблонам реальных документов, но не описывает происхождение шаблонов подробнее.

Пять строк preview уже выявили импорт-блокеры: вложенные перекрывающиеся `name`/`first_name`/`last_name` и `address`/компоненты; англоязычные документы и сущности вне текущего русского домена (IP, geolocation, NIE); нетронутая запись может содержать 3+ типизированных сущностей, но это ещё не целевой русский медико-персональный контраст. Пагинация полного rows API вернула HTTP 429, поэтому статистика всех 5 318 строк, корректность всех Unicode offsets и пересечения train/test не подтверждены. Статус источника — `HOLD` до полного аудита; в корпус ничего не импортировано.

Дополнительные словари подходят только для составления кандидатного списка, не для копирования текстов. [Human Disease Ontology](https://www.disease-ontology.org/resources/do-resources/) указывает CC0 для DO content. В [Wikidata](https://www.wikidata.org/wiki/Wikidata:Licensing) структурированные данные CC0, тогда как текстовые пространства имеют иные условия. [OpenStreetMap](https://www.openstreetmap.org/copyright/en?locale=en-GB) допускает коммерческое использование по ODbL с атрибуцией и условиями share-alike; для этого корпуса это лишняя лицензионная нагрузка. Встроенные адресные списки проекта [russian-data-generator](https://github.com/DooGer1/russian-data-generator) имеют неясное происхождение, несмотря на MIT для репозитория.

Условия CC BY 4.0 допускают коммерческое использование при выполнении атрибуции, указании лицензии и изменений: [текст лицензии](https://creativecommons.org/licenses/by/4.0/). «Бесплатный» в этой проверке означает отсутствие платы за использование; обязательства лицензии всё равно фиксируются в реестре источников.

## Принятая группировка документных номеров

Текущий классификатор предсказывает плоские BIO-метки. В действующей онтологии `PASSPORT` означает паспорт; полис ОМС, карта пациента, направление, водительское удостоверение, номер истории болезни и произвольный номер документа отдельного класса не имеют. Нельзя переносить их под `PASSPORT` или обучать модель без метки.

Архитектурное решение принято в [ADR_DOCUMENT_TAXONOMY.md](ADR_DOCUMENT_TAXONOMY.md): родитель `DOCUMENT` — метаданные маршрутизации, модель предсказывает конкретную leaf-метку, а `PASSPORT` сохраняет текущий смысл. Новые типы добавляются только в отдельном immutable corpus release. Сами внешние материалы нужны для изучения форматов, типов полей и методики контрастной проверки; исходные строки, записи, шаблоны предложений и разметка не копируются в authored corpus.

Контекст типа обязателен для `OTHER_DOCUMENT_ID`: голая последовательность цифр не становится документом только из-за длины. Телефон и СНИЛС остаются отдельными метками. Даты, дозировки, давление, температура, кабинет, номер исследования или внутренний счётчик сами по себе не относятся к документам. Authored-примеры СНИЛС используют значения с контрольной суммой, принятой текущим проектным валидатором; числа той же длины без контекста и случайные цифровые строки остаются hard negatives.

## Контрастная матрица для авторских русских примеров

Каждая строка ниже — отдельная смысловая проверка. Полные учебные записи должны соединять несколько позитивных классов, близкие отрицательные числа и длинную связную медицинскую историю; точные границы перепроверяются независимым редактором.

| Пара/сочетание | Разметка и ожидаемое поведение |
|---|---|
| «Приём перенесли на улицу Пирогова; Иван Пирогов указан лечащим врачом» | Название улицы — `STREET`, имя врача — `PER`; фамилия внутри названия улицы не размечается повторно как человек. |
| «Назначено наблюдение при болезни Паркинсона; Паркинсон описал этот симптом в 1817 году» | Болезнь целиком — `DISEASE`; отдельно названный исторический человек — `PER`. Вложенных перекрывающихся spans нет. |
| «Исключить болезнь Альцгеймера; в семейном анамнезе болезнь Паркинсона у деда» | Обе болезни — `DISEASE`, независимо от отрицания и родственника. Текущий authored validation пропустил разметку болезни Паркинсона; исправлять только в новом immutable релизе. |
| «Телефон +7 …; кабинет 214; давление 120/80; доза 500 мг; дата 12.03.2026» | Меткой `PHONE` отмечать только номер телефона по текущей политике; кабинет, давление, доза и дата — числовые hard negatives. |
| Валидный по текущему проектному правилу СНИЛС в персональном контексте и похожая случайная последовательность в поле образца | Первый — `SNILS`; второй — отрицательный пример. Значения с неверной контрольной суммой не добавляются как positive, пока отдельное решение не изменит текущую проверку СНИЛС. |
| Паспорт, полис ОМС, карта пациента, направление, водительское удостоверение, история болезни, номер исследования | Паспорт размечается `PASSPORT`; утверждённые дочерние типы используют `OMS_POLICY_ID`, `PATIENT_CARD_ID`, `MEDICAL_RECORD_ID`, `REFERRAL_ID`, `DRIVER_LICENSE_ID` или `OTHER_DOCUMENT_ID`. Номер исследования — отрицательный пример, если он не назван документом. |
| Смешанная запись: человек + улица-эпоним + болезнь-эпоним + телефон + СНИЛС + паспорт/полис + даты, анализы и случайные числа | 3–8 позитивных spans минимум из нескольких групп, рядом отрицательные числа; одна запись не должна превращаться в перечень с cue-словами. Группы/шаблоны остаются изолированы между train, validation, test и sealed challenge. |

Лексические кандидаты для болезни: Паркинсона, Альцгеймера, Дауна, Марфана, Бехчета, Ходжкина. Улицы и персоны должны иметь отдельные контексты. Список — только семена для новых авторских формулировок; словарная запись не заменяет редакторскую проверку.

## Применение источников: только структурное вдохновение

Цель запроса — найти источники без платы и с ясным правом коммерческого использования. Ни один пример, текст, шаблон предложения или строка разметки не переносится: источники нужны только для изучения структур полей, форматов и методик проверки.

|---|---|

## Порядок работы

1. Продолжать read-only аудит закреплённых ревизий и их лицензий/provenance; не переносить строки, записи, шаблоны предложений и аннотации.
2. Использовать только документированные типы полей, форматы и методики для самостоятельной разработки разнообразных русских сценариев.
3. Проверять точные spans, checksum-ы, документы с несколькими сущностями, длинные медицинские заметки, контрастные эпонимы и числовые hard negatives; затем проводить слепую редакторскую проверку.
4. Включать принятые авторские примеры только в новый immutable corpus release. Не менять 1.16.0; не настраивать по закрытым test/challenge. До независимой оценки и прохождения порогов кандидат остаётся `HOLD`.

Ни один внешний источник или новый корпус на этом шаге не импортирован; улучшение качества модели не оценивалось.
